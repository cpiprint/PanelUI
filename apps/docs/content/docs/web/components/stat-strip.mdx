Use it for two to four figures that belong together and need no chart: the state of a repository, the totals under a run. Each figure has its label over it and, where there is one, the change under it.

The figures share the width equally, with a rule between each and the next.

It has no room for a sparkline or an icon. With more than four figures, or with long values, the columns get too narrow to read. Stack them with `orientation="vertical"`, or use a grid of cards.

## Usage

```tsx
import { StatStrip } from "@/components/panelui/stat-strip"
```

```tsx
<StatStrip>
  <StatStrip.Item label="Issues">
    48
    <StatStrip.Trend value={-11} goodDirection="down" />
  </StatStrip.Item>
  <StatStrip.Item label="Review">
    3.2 <StatStrip.Unit>h</StatStrip.Unit>
  </StatStrip.Item>
</StatStrip>
```

## Composition

```tsx
<StatStrip>
  <StatStrip.Item label="…">
    … <StatStrip.Unit>…</StatStrip.Unit>
    <StatStrip.Trend value={…} />
  </StatStrip.Item>
</StatStrip>
```

- **`StatStrip.Item`** — One figure. Its children are the value and `label` is what it measures.
- **`StatStrip.Unit`** — The unit after a figure, drawn smaller and quieter than the number.
- **`StatStrip.Trend`** — How the figure has moved. It takes the change as a number, writes the sign and picks the colour.

## Examples

### Stacked

`orientation="vertical"` puts the figures one over the other with a level rule between them, which fits a narrow column. Children of `StatStrip.Trend` are a caption after the change, and `format` writes the change in a unit other than percent.

  return (

## API Reference

### StatStrip

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `orientation` | `'horizontal' \| 'vertical'` | `horizontal` | Side by side with upright rules, or stacked with level ones. |

### StatStrip.Item

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `ReactNode` | — | What the figure is. Drawn over it. |
| `valueClassName` | `string` | — | Extra classes for the figure. |
| `labelClassName` | `string` | — | Extra classes for the label. |

### StatStrip.Trend

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number` | — | The change. Its sign decides the direction; zero is drawn as no change. |
| `format` | `(magnitude: number) => string` | `(magnitude) => ${magnitude}%` | Writes the change. Defaults to a signed percentage: "+7.8%". The number it is given is already positive, and the sign is added for you. |
| `goodDirection` | `'up' \| 'down'` | `'up'` | Which direction is the good news. `down` for latency, cost, open issues. |

Every part also takes the props of the element it renders, and a `className`.

## Notes

### Trend colours

`StatStrip.Trend` is drawn in the success colour when the figure moved the good way, in the destructive colour when it moved the bad way, and in the muted colour when `value` is zero.

Up is good unless you say otherwise. For a figure where less is better, such as review time, cost or open issues, pass `goodDirection="down"`.

### Writing the change

`format` is given the size of the change without its sign and returns the text, which defaults to a percentage. The sign is added for you, with a true minus so a column of changes lines up.

### Labels

Keep a label to a word or two. A label too long for its column wraps to a second line, which pushes its figure down out of line with the others.

### Narrow strips

The strip measures itself, not the screen. Under 24rem wide the figures are set one size smaller and the padding is tighter, so three figures still fit across a phone. The strip has to be given a width for that to work: it fills its container, and inside something that shrinks to fit its contents it has nothing to fill.

### Spacing

Each item is padded on the sides that face a rule. To change it, set `--pu-gap-x` on a horizontal strip or `--pu-gap-y` on a vertical one, with a class such as `[--pu-gap-x:1.5rem]`.

### Order in the markup

It is a description list. Each label is the term and its figure the description, so a screen reader says "Issues, 48".

### Server Components

Stat Strip holds no state, so it is not a client module. It can be rendered from a Server Component as written, and it adds no JavaScript to the page.
